## 참고 자료 우선순위 및 충돌 처리 원칙

| 순위 | 자료 | 적용 범위 |
| --- | --- | --- |
| 1 | `[Spark] 요구사항정의서(v2).pdf` | 화면 구성, 기능 범위, 입력·검증, 상태, 사용자 동작·흐름 |
| 2 | `ReSparkSQL_Last.pdf` | Mock 데이터 필드·타입 참고 (화면 필드의 데이터 근거) |
| 3 (보조) | `이벤트스토밍 2차.pdf` | 과거 흐름 이해용. **화면/경로를 여기서 새로 만들지 않음** |

충돌 처리

1. 이벤트스토밍 ≠ 요구사항(v2) → **v2 화면·동작을 따른다.**
2. 이벤트스토밍에만 있는 화면은 **제안 경로에 자동 추가하지 않는다.**
3. SQL과 v2 필드가 다르면 화면은 v2 UX를 우선하고, 데이터 불일치는 갭 분석 «요구사항 ↔ SQL 불일치»를 본다.
4. «제안» 경로는 모두 **요구사항(v2) 기능 ID**에 대응한다.

경로 표기

- **현재**: 코드에 존재하는 App Router 경로
- **제안**: 요구사항(v2) 충족을 위해 추가가 필요한 경로(아직 없음)
- **보조**: v2에 번호 기능으로 명시되지 않은 탐색용 화면 (예: `/admin` 대시보드)

## F. 디자인 검토 — 추가 화면·상태 (v2)

1. 헤더: 카테고리 / 알림 / 채팅 배지 / **KO·EN**  
2. 가입: 인증 단계, 비번 규칙, 마케팅 동의, 소셜, 성공→메인  
3. 판매: 갤러리 업로더(10), AI 시세, 금지품목, 1·2차 카테고리, **$0~100**  
4. 판매 수정 + 삭제 모달  
5. 목록: 5×5, 카드 찜, 가격 min/max  
6. 상세: 갤러리, 판매자 평점 블록, 신고  
7. 채팅: 번역·수락/결제 시스템메시지·경고·도배잠금  
8. 판매자 정보 입력 (수락 후)  
9. 결제: 배송지 시트, 약관 모달, 멤버십 표시  
10. 마이페이지: 계좌·배송지·리뷰·제재·프로필  
11. 구매/판매 상세 + 취소 전용  
12. 고객센터 분리(FAQ/공지/문의)  
13. 관리자: 회원·거래·신고 상세, 공지/FAQ 에디터(예약 캘린더), 답변 CRUD  

공통 상태: 로딩 / 빈 / 권한없음 / 검증오류 / MOCK 안내 / 확인 모달
