분석일: 2026-11-14  
재검토일: 2026-11-14 (참고 자료 우선순위 변경)  
범위: **분석만** (코드 미수정)

## 참고 자료 우선순위 및 충돌 처리 원칙

| 순위 | 자료 | 적용 범위 |
| --- | --- | --- |
| 1 | `[Spark] 요구사항정의서(v2).pdf` | 기능·정책·화면 범위·필수 입력·검증·상태 변경·사용자 동작 |
| 2 | `ReSparkSQL_Last.pdf` | 테이블·컬럼·타입·관계 등 데이터 구조 |
| 3 (보조) | `이벤트스토밍 2차.pdf` | 과거 도메인 이벤트·업무 흐름 이해용. **필수 구현 근거로 사용하지 않음** |

충돌 처리

1. 이벤트스토밍과 요구사항(v2)이 다르면 **요구사항(v2)을 따른다.**
2. 이벤트스토밍에만 있고 v2에서 확인되지 않는 항목은 **필수 구현에 자동 추가하지 않는다.** (하단 «이벤트스토밍 전용 참고»에만 표시)
3. SQL(Last)과 요구사항(v2)이 불일치하면 **임의로 한쪽을 채택하지 않고** «요구사항 ↔ SQL 불일치»에 보고한다.
4. 구현 상태 판정은 **코드에서 확인된 사실**만 반영한다.

## 요약

| 구분 | 수 |
| --- | ---: |
| 전체 기능 (요구사항 v2 기준) | **107** |
| 구현 | **6** |
| 부분 구현 | **36** |
| 미구현 | **65** |
| 확인 불가 | **0** |

> 재검토 결과: 기능 ID·상태 집계는 유지. 이전 문서에서 이벤트스토밍을 갭 근거처럼 서술하던 부분만 수정했으며, v2에 없는 기능을 누락으로 잘못 넣은 항목은 확인되지 않았다.

판정 기준

- **구현**: 코드에서 해당 기능의 주요 화면·동작·Mock API가 확인되고, 요구사항(v2)의 핵심 목적과 대체로 일치
- **부분 구현**: 관련 화면/API는 있으나 요구사항(v2) 대비 필수 UI·규칙·상태가 빠짐
- **미구현**: 관련 페이지·컴포넌트·API가 코드에서 확인되지 않음
- **확인 불가**: 요구사항만으로 범위를 확정할 수 없음 (본 분석 없음)

우선순위 (Stage 1 프로토타입 관점, 근거는 v2)

- **P0**: 가입~탐색~거래~마이페이지 핵심 흐름
- **P1**: 고객센터·신고·관리자 운영 UI
- **P2**: v2에 있으나 Stage 1에서는 스텁/단순 Mock으로 충분
- **P3**: 외부연동·배치·게시판 설정 등 Stage 2 성격이 큼

## 3. 이벤트스토밍 전용 참고 (필수 구현 아님)

`이벤트스토밍 2차.pdf`는 이미지 위주라 본문 텍스트 추출이 불가하고, **목차(아웃라인)만** 확인된다.

목차상 주제: 회원가입, 로그인/로그아웃, 상품 CRUD, 채팅, 결제, 구매내역/확정/취소, 배송지 CRUD, 정산요청·조회·취소, 카테고리 CRUD, 관리자(상품삭제·회원·운영자) 등.

재검토 결과

- 위 주제는 **요구사항(v2)에도 대응 기능이 존재**한다. 이벤트스토밍에만 있는 필수 기능을 잘못 추가한 사례는 없다.
- 이전 문서 §3에서 «이벤트스토밍 대비 공백»으로 서술하던 배송지·정산·카테고리·판매자 정보입력은 **요구사항(v2) 기준 미구현/부분 구현**으로 이미 본표에 반영되어 있다.
- 이벤트스토밍의 과거 흐름이 v2와 충돌할 경우 **v2를 따르며**, 본 분석에서 이벤트 흐름을 구현 요건으로 승격하지 않는다.
- **이벤트스토밍에만 확인되고 v2에서 확인되지 않은 필수 기능: 없음** (목차 수준 한정).
